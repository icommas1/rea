# REA native backend: constrained ELF layout

A separate HTTP service around the **official REA 6.4.0 pwntools ELF adapter**. It does not replace the existing JavaScript-analysis Site or expose REA's general CLI/MCP surface.

## What works

Linux x64 only; accepts ELF64, little-endian, x86-64 EXEC/DYN/REL artifacts. Returns their SHA-256, byte count, sections, segments, original symbols and relocations, dependency names, GOT candidates and static mitigation candidates with upstream limitations. This is real structural binary analysis, not a strings-only scan.

**Not supported:** decompilation, general disassembly, reliable PLT inference, debugging, native program execution, arbitrary commands, paths or URLs, PE, Mach-O, ARM, archives or core dumps. Full REA native workflows need Hopper, Ghidra or IDA and are outside this small service.

The official adapter may attempt restricted Unicorn instruction emulation to infer PLT entries. This is distinct from launching the uploaded program as a host process. This service's 320 MiB Python address-space cap prevents Unicorn's 1 GiB allocation in the tested executable, so PLT inference failed and is explicitly reported as incomplete. Empty inventories never prove absence. The API does not call pwntools `.libs`, `.maps`, `.libc`, `process()` or any other target-launch workflow.

## API

- `GET /healthz`: public, reports `status` and `analysisEnabled`. Authentication missing/too short means `analysisEnabled: false`.
- `GET /v1/capabilities`: authenticated, reports formats, limits and exclusions.
- `POST /v1/analyze`: authenticated; body must be raw `application/octet-stream`, uncompressed. No multipart, filename, path, URL or query options.

Authenticated endpoints require `Authorization: Bearer <REA_API_KEY>`. `REA_API_KEY` must be at least 32 bytes and should be a securely provisioned high-entropy server secret. It is never generated by this package. Configure it only after approval in the hosting secret interface and the calling Site's server-side secret store. **Never put it in browser JavaScript, source control, a URL, a chat message or a client-visible configuration.** `oai-*` headers do not grant access. No CORS access is enabled.

Successful JSON includes `ok`, `profile`, `provider`, `artifact`, `layout`, structured `diagnostics`, and `limitations`. It is a verified provider-result projection, not a modified REA Evidence envelope. Raw parser diagnostics and temporary paths are withheld. Symbol names and other artifact strings are untrusted data: escape them when displaying them and never treat them as instructions. A future MCP bridge must project a bounded summary if its output budget is smaller than 2 MiB, explicitly describing omitted rows.

Failures: `401` authentication, `404` unknown route, `413` upload limit, `415` unsupported type/profile, `422` invalid artifact/resource/output limit, `429` single slot occupied, `503` disabled/provider unavailable/uncertain cleanup, `504` timeout/cancellation. Internal errors are sanitized. No partial successful reports are returned.

## Bounds and isolation

- One upload/analysis at a time; no queue; at most 16 HTTP connections.
- Upload at most 4 MiB, 10-second upload deadline, 5-second header deadline.
- Analysis wall deadline defaults to 30 seconds. `ANALYSIS_TIMEOUT_MS` is clamped to 15–30 seconds; upstream itself has a 30-second limit. Slow shared CPUs can time out even on valid inputs.
- Complete output at most 2 MiB. Python: 320 MiB address-space, 12 CPU seconds, 2 MiB per-file write, 64 descriptors, no core dumps. Node starts with a 128 MiB V8 old-space limit.
- These are **not a summed hard RSS limit**. A hosting container memory limit is still required. This is bounded parsing, not a hardened malware sandbox: parser/library vulnerabilities remain possible. Only analyze files you are authorized to inspect; do not expose this service as a public anonymous malware-analysis facility.
- Private randomly named temporary directories and non-executable `0600` uploads. Fixed interpreter/bridge paths; `shell:false`; no request-controlled command arguments. No deployment secrets are passed to Python. No code files are writable by the Docker service user.
- REA owns and verifies child process groups using run tokens, parent and group identity. The fixed Python limiter uses `exec`, so the launcher's command-string check is deliberately omitted via its supported `expectedCommand:null`; other ownership checks remain active.
- Cancellation and normal shutdown abort active work and attempt verified process cleanup. Any reported uncertain cleanup disables subsequent analysis. Files are removed before a success response. SIGKILL, host failure or a forced shutdown can prevent cleanup; use ephemeral storage, never volumes, and reset the container after such failures. There is no promise of cleanup after a host crash.
- No app telemetry, background polling, database, persistent job storage, outbound target fetching or scheduled work.

## Local setup and checks

Requires Linux x64, Node 24.11+ (24.x), Python 3.11/3.12, `ps` and a C compiler for integration fixtures. Commands run inside this directory:

```sh
npm ci --ignore-scripts
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
export PATH="$PWD/.venv/bin:$PATH"
npm test
npm run test:integration
python3 scripts/measure-rss.py
npm start
```

The final command intentionally starts disabled without `REA_API_KEY`. Tests use an obviously non-production, in-memory test credential; it grants access to no deployed service. Integration tests compile a harmless C object and **never execute the resulting artifact**.

## Deployment and $0 boundary

A Dockerfile, Railway configuration and explicit-free Render Blueprint are included. The pinned `node:24.21.0-bookworm-slim` tag is listed in the official image manifest (https://raw.githubusercontent.com/docker-library/official-images/master/library/node); local checks used Node 24.19.0, so the exact container runtime still requires testing. No service is deployed by these files, no credential is created, and automatic deployment is disabled in the Render Blueprint. Bind address is `0.0.0.0`; hosting `PORT` is honored.

For this repository's `native-backend/` subdirectory, configure the hosting service's root directory to `native-backend` and Dockerfile path to `./Dockerfile`. Alternatively extract this directory into a standalone repository and use the files unchanged. A root-level Render Blueprint must set `rootDir: native-backend`; the provided Blueprint assumes this directory is the service root. Render's spec: https://render.com/docs/blueprint-spec . Do not omit `plan: free`; do not switch to a paid plan, attach a paid disk, add paid add-ons or configure payment details to bypass a limit. Any cost requires separate approval.

Railway provisioning was blocked by the account's free resource limit during this work; no upgrade was made. A small image/resource footprint does not establish ongoing zero-cost availability. Free hosting can sleep, be throttled, exhaust credits/quotas or stop. Render Free is a candidate, not a verified live deployment. Its small shared CPU can increase analysis times and cold starts. Check the current dashboard's free-plan availability and terms before deploying. Do not implement keep-alive traffic to defeat free-tier sleep.

Before public use: build/test the Linux/amd64 image under a 512 MiB container limit, validate the actual host's CPU/time behavior, securely provision authentication, verify invalid credentials fail, and run a real authorized fixture end to end. Do not connect the existing Site until these checks pass.

## Verification performed

On the local Linux x64 executor using Node 24.19.0 and Python 3.12:

- 12 HTTP/security/lifecycle tests passed (with integration tests separately skipped in the default run).
- 4 real integration tests passed: compiled ELF symbols/relocations, malformed input, real process cancellation, and HTTP cancellation followed by a healthy next request.
- A 43,432-byte existing ELF executable was read, **not executed**: 30 sections, 61 symbol rows and 75 relocation rows. PLT inference emitted the expected constrained-memory warning.
- Sampled combined Node/Python RSS was about **87 MiB** on that one small fixture (~0.4 seconds locally, 10 ms sampling). This is not a worst-case bound, exact peak, hosting benchmark or whole-container measurement.
- Installed local dependencies were about 96 MiB of Node modules plus 210 MiB of Python environment. A full image is expected to be several hundred MiB, but **Docker was unavailable: image build, compressed size, target Python 3.11 compatibility and deployment have not been verified**.

Locks pin REA and Python packages. The local npm test dependency tree came from an already installed official `rea-agents@6.4.0` tree with its existing integrity lock; a fresh Docker `npm ci` remains to be verified. REA internal module paths are version-specific, so upgrades require regression testing.
